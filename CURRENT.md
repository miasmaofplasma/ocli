## Goal

`ocli new` produces a real note in the vault: the moment the tool stops being a reader. Best first write command — render + `File::create_new` (atomic refuse-to-overwrite via `O_EXCL`), no D11 surgical-edit machinery needed. Along for the ride: `list` repo filtering and `open`.

## Slices (each ends compiling and tested)

1. **Branch → ticket inference (D20/D25):** named captures from `GitContext.branch` → composed ID via `[tickets] id`; the D20b hard-require (`new` refuses off-pattern branches); the previously-removed branch→ticket functions come back here.
2. **Value map + renderer (Q8, D12/D21/D22):** merged layers (`--set` > key-derived > branch captures > `[template.values]`) consumed by a dumb renderer over the template text; grammar is `{{VALUE:name}}` + `{{DATE:<house format>}}` (exact — see decisions); anything else hard-errors naming the line.
3. **Field-set primitive + fills:** build the shared frontmatter field-setter now — `set_field(fm_text, field, value)`: locate the field region (top-level key line + continuation lines, the D11 splice unit), typed emission (string quoted/escaped, olink auto-wrapped `"[[...]]"`; D18), field absent → hard error naming the field. Pure text-in/text-out; `new`'s fills are its first consumers, Phase 6's `status`/`fm` reuse it (insert-if-absent, multi-edit, atomic write, retry stay Phase 6 — `new` needs none of them). `ftypes` moves out of `config.rs` now (its second consumer has arrived, D31). Fills: `repo` (D13, `Olink` from the snapshot, `--repo` overrides), `description` (D24, only with `--description`). `Created` needs no fill — it's the template's `{{DATE}}` (value pipeline); no `status` fill (template encodes initial state).
4. **Write + dispatch:** `File::create_new` into `features/<ID>.md`; wire into `main`.
5. **Rides along:** `list` repo filtering (**DONE 2026-09-12** — `--all-repos` widens; outside a repo the whole vault lists, see log) and `open` (**DONE 2026-09-13**, D29 — percent-encoded absolute path, `open` crate → `xdg-open`).

- [x] **Template audit** (done 2026-09-12, read-only against the real template): placeholders are exactly `{{DATE:YYYY-MM-DD HH:mm}}`, `{{VALUE:FeatureType}}`, `{{VALUE:TicketNumber}}` — all quoted, all in frontmatter, none in the body (Meta Bind `INPUT[...]` is literal). `status:` empty + `done: false` hardcoded → no status fill needed. - [x] **Time crate + format** (settled 2026-09-12): `chrono 0.4`, `default-features = false, features = ["clock", "std"]` (verify exact set at add; **no `chrono-tz`** — the local offset ships with `clock`). Entire surface: `Local::now()` + integer accessors, padded via std `{:04}`/`{:02}` — no strftime, no token parser. **One house format, `YYYY-MM-DD HH:mm` local time**, shared with Phase 6's D19 entry appends; the format argument is **exact-matched, never parsed** (`{{DATE:...}}` recognized structurally; any other arg → hard error naming the line + supported format — no silent divergence). `{{TIME:...}}` dropped from the grammar (audit found none; unrecognized → loud error; one-line add if ever needed — D12 amended at promotion). `now()` captured once per render.
- [x] **Q8 / render pipeline** (settled 2026-09-12, empirically): **substitute on text, validate after, never serialize.** One scan pass classifies `{{VALUE:name}}` and `{{DATE:<exact house format>}}` (anything else → hard error naming the line), then substitution from the merged `ValueMap` (`BTreeMap<String, String>` + provenance for D20c conflicts); fills (`repo`, `description`) are post-render line edits. Rejected: parse→mutate→serialize via yaml_serde `Value` — proven by running it on the real template's frontmatter (`/tmp/yamldemo`): parses fine (all placeholders quoted) but the emitter rewrites 18/21 lines (empty fields → `null`, quote style, list indent), and unknown placeholders pass through silently instead of failing loud. Parse the *rendered* frontmatter as an optional post-render validation check only.
